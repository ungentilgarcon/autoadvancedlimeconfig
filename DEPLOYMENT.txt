LibreMesh firmware deployment
==============================

See README.md for the full configuration snapshot, optional VLAN design,
deployment examples, security notes, and failsafe/restore details.

Optional VLAN configurations can be validated or applied per device with the
`vlans` subcommand. Applying starts a 180-second automatic rollback timer;
confirm the returned change ID with `vlan-confirm` only after verifying
connectivity. See README.md for configuration templates and policy details.
VLAN Wi-Fi keys are read from the ignored, mode-600 `.pass` file; initialize it
from `.pass.example` if needed. Never commit or print `.pass`.

deploy-libremesh.py retrieves the current stable OpenWrt version and profile
from the Firmware Selector's configured upstream, then requests a custom
LibreMesh image from the Selector's ASU build service. It verifies the
downloaded sysupgrade image against the ASU SHA-256 before staging it.

Supported explicit profiles:

  redmi-ax6000-ubootmod
  aruba-ap-303

The package list in firmware-selector-packages.txt was reconstructed from the
existing note in script_config_lime_AP.txt: wpad-mesh-openssl, luci, nano-full.
Add other packages there, or pass --extra-packages "pkg-one pkg-two".
The list is sent as OpenWrt packages; LibreMesh's current default flavor and
the profile's device packages are taken from the live Selector configuration.

Build only:

  python3 deploy-libremesh.py build --device redmi-ax6000-ubootmod
  python3 deploy-libremesh.py build --device aruba-ap-303 \
    --extra-packages "mwan3 luci-app-mwan3"

Build and stage on the existing PICOT0 without flashing:

  python3 deploy-libremesh.py deploy \
    --device redmi-ax6000-ubootmod --host root@PICOT0

For any other model use its OpenWrt board name, e.g. --device aruba,ap-303
(profile ids and the shortcuts also work). Staging captures that device's own
current /etc/config as its live rollback.

Only add --flash after reviewing the image and staged rollback. Flashing
requires typing the exact board confirmation. The upgrade uses sysupgrade -c
to preserve the current device configuration. SSH host-key checking remains
enabled; accept/verify each AP's host key before deployment.

With --failsafe-dir backup-PICOT0-2026-10-30 (any directory with a
known-good etc/config), that backup is archived and staged on the device at
/root/libremesh-failsafe/picot0-config.tar.gz. The deployment also captures
the pre-upgrade live config on every device. To restore, log into the device
(use local/serial access if SSH is unavailable) and run:

  /root/libremesh-failsafe/restore-libremesh-config.sh saved

The saved restore applies that backup as-is (including its hostname and
addresses), so stage it only on a suitable node. To restore the device's own
captured pre-upgrade config instead:

  /root/libremesh-failsafe/restore-libremesh-config.sh live

The restore prompts for a confirmation token, saves the current config first,
then restores UCI files and restarts LibreMesh/network services.

To drop VLANs from one node and keep it meshing with VLAN nodes:

  python3 deploy-libremesh.py vlans --device BOARD --host root@HOST --disable

Experimental fleet controller
-----------------------------

See README.md, "Fleet upgrades (experimental)", before use. This controller
has not been validated on the physical fleet; use an isolated pilot and retain
local/serial recovery access. Automatic firmware rollback is not provided.

Copy fleet-inventory.example.json to the ignored fleet-inventory.json and
provide each node's SSH host, device profile and mesh IP. Set SSH passwords,
if needed, in the mode-600 .pass file using FLEET_SSH_PASSWORD or a
FLEET_SSH_PASSWORD_<NODE> override; password SSH requires sshpass. Firmware
board checks currently require key-based SSH. Secrets are not interpolated
from .pass into UCI change files.

Copy a fleet-changes/*.example.json template to a private ignored name and
edit it. Review with --dry-run (which prints the UCI lines), then:

  python3 fleet-libremesh.py backup
  python3 fleet-libremesh.py config fleet-changes/my-change.json --id change-001
  python3 fleet-libremesh.py status
  python3 fleet-libremesh.py rollback change-001

Rollback applies only to a pending, unconfirmed change. A config-breaking
change is staged and scheduled on affected nodes, but arming and confirmation
are best effort, not atomic; partial failures can leave nodes on different
configurations. Peer checks only include selected nodes with mesh_ip entries.
The firmware subcommand performs sequential sysupgrade -c with health checks,
not firmware rollback. Confirm the ignore rules for any custom files and
protect backups and command output, which may contain secrets.

For archive comparison, per-node dry runs and experimental deployment, run:

  python3 fleet-config-ui.py

Select changed files and/or comma-separated packages and an inventory with a
distinct mesh_ip for each node, run the dry run, then type DEPLOY when prompted.
Package-only deployments do not require backups. APK simulates dependencies
using cached indexes; OPKG checks package availability only. Update indexes
on the nodes first if needed. The dry run does not install packages or validate
UCI syntax; UCI files are validated at staging. Packages and dependencies are
installed before files and are not rolled back if anything fails. A failed or
timed-out install can be partial or still running. Nodes need flock.
Scheduling and confirmation are best effort, not atomic;
partial confirmation or lost nodes can require manual recovery. Health checks
do not prove routing convergence. Use current helper versions, a test fleet,
and independent recovery access; do not run older controllers concurrently.

Firmware deployment deliberately preserves the existing network configuration;
the separate optional VLAN command adds VLAN 10/20 on selected Wi-Fi radios
with a timed rollback. It leaves Ethernet ports and the existing untagged main
network unchanged. VLAN 30 and Ethernet port tagging are not
implemented. Do not pass an unreviewed UCI-defaults script with --uci-defaults.

Automatic WAN detection (any LAN port with Internet becomes a WAN uplink;
batman-adv picks the gateway):

  python3 deploy-libremesh.py autowan --device BOARD --host root@HOST [--action enable|disable|status]
