# Model-specific firmware fixes

Put image overlay files under `fixes/<target>/<subtarget>/<profile>/files/`.
Paths below `files/` become absolute paths in images for that exact target
and profile. For example:

```text
fixes/ipq40xx/generic/aruba_ap-303/files/usr/sbin/example-tool
fixes/mediatek/filogic/xiaomi_redmi-router-ax6000-ubootmod/files/usr/sbin/example-tool
```

The matching build automatically includes regular files with their permissions
using the local ImageBuilder, including builds initiated by fleet firmware
upgrades. A dry run lists the included paths. A prebuilt image supplied to
fleet firmware with `--image`, or to `stage`, is used unchanged and does not
have fixes added to it. This directory is not ignored by
Git: never put credentials or sensitive configuration here. For sensitive
fixes, use the same directory structure outside the repository and pass
`--fixes-dir /path/to/private-fixes` to the build, deploy or fleet firmware
command. The selected directory replaces, rather than merges with, `fixes/`.
Ensure the alternate location is not tracked by Git.

Model overlays are never sent to the remote firmware build service. Symlinks, special
files and setuid/setgid files are rejected. Overlay files may not overwrite
files generated by `--inject-pass` or `--uci-defaults`.

An overlay only embeds files: it does not automatically execute a fix or
guarantee that a saved configuration will not override an image file. In
particular, first-boot defaults are not a reliable way to change a preserved
configuration during `sysupgrade -c`. Design and test each fix for both clean
installs and configuration-preserving upgrades before deployment. Review
target, profile, permissions, activation and recovery on one device first.

The AP-303 overlay contains an experimental radio recovery watchdog. The local
image builder creates its boot service link when all three watchdog files are
present. See the AP-303 radio recovery section in the main README for its
probes, limits, risks, disabling instructions, and upgrade caveats. Its
underlying connectivity issue is not proven fixed; test one device before
wider deployment. No Redmi AX6000 fix is supplied.
